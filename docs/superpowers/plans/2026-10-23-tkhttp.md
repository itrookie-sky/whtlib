# tkhttp 实施计划

> 实施方式：使用 executing-plans 在当前会话逐项完成。用户已批准设计并要求开发；不采用 TDD，不执行自动代码审核。

**目标：** 实现可注入标准库连接池和共享累计日志的 HTTP 客户端，每次调用最多执行一次 `http.Client.Do`。

**架构：** `adapter.LogAcc` 声明共享契约，`logx` 提供保持旧 API 的薄适配层；`tkhttp` 通过 Config 管理基本参数，通过 With 选项注入依赖。所有请求状态独立，初始化后 Client 可并发复用。

**技术栈：** Go 1.26.3，标准库 net/http、net/url、encoding/json、context；不新增第三方依赖。

**设计：** [HTTP 设计](../specs/2026-10-23-tkhttp-design.md)。

## 全局约束

- 在当前仓库 main 开发，不使用分支或 worktree；完成后直接 push。
- tkhttp 不配置、导入或调用 tkretry，不实现重试或跨调用统计。
- 基本参数使用 Config；请求接口使用可省略的 `configs ...RequestConfig`，最多一份。
- 无注入连接池时创建独立标准库默认池；注入时借用原实例，仅清理自有空闲连接。
- LogAcc 由 adapter 声明，通过模板注入；不声明 Factory，不依赖具体日志实现。
- 不改变已有字段类型和链式返回类型；命名返回值、分行错误处理、中文注释。
- 已获准编写相关测试；只运行受影响包的本地测试、race、vet 和编译检查。
- 远端基线为 `16c543dfeb7400b9ca7bfc545fb1fa56c5ac1ca6`；保留已有设计文档排版变更。

## 重点验证

- nil/typed nil 配置依赖和失效 Clone 在网络前报错；关闭日志时不调用模板。
- Header、URL、JSON、超时和可选配置数量错误在网络前报错，日志不含原始敏感输入。
- 取消、限额、状态及解码错误保留可用 Response 和错误链，响应体始终关闭。
- 注入池身份、共享复用、优先级及生命周期正确，重定向不转发签名和 Header。
- 每次调用一条日志；并发字段、起点、源码位置独立，Clone 不累积额外 Skip。
