# tkua 实施计划

目标：新增框架无关的 UA 结构化解析组件，提供可比较的字符串枚举；常量统一维护在 consts.go。

实现选择：复用 uap-go 的内嵌规则解析客户端、操作系统、设备品牌型号，再封装浏览器、引擎、平台、终端、应用容器、架构和机器人类别。相较于完全自行维护正则，减少重复实现并复用上游设备覆盖；不引入服务端 API 或运行时规则下载。

接口：`Parse(raw string) (Result, error)` 使用懒初始化默认解析器；`New(Config) (*Parser, error)` 创建可并发复用实例；`(*Parser).Parse(raw string) (Result, error)` 返回独立值。Config 包含 MaxLength 和 CacheSize，零值使用默认值，负值报错。

结果：Raw、Client、Browser、OS、Platform、Device、Engine、App、Architecture、Bot。版本保存原始字符串及 Major/Minor/Patch/Build；枚举未知值为空字符串，识别名称另行保留，避免未来规则扩展丢失信息。空 UA 和未知内容不是错误。长度超限、配置错误、未初始化实例在 error.go 集中声明并支持 errors.Is。

边界：仅解析 UA 自报信息，不验证 bot 身份，不猜测 Windows 11、伪装成 macOS 的 iPad 或被隐藏的 CPU；不处理 Client Hints。平台表示 OS 生态，终端形态与客户端种类分离。规则匹配按具体产品优先于兼容标记的顺序执行。返回数据不暴露上游缓存指针。
