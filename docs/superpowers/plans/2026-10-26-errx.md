# errx 实施计划

目标：按用户确认的全部建议实现 extension/errx，使用 Go 1.27.3 标准库，不增加依赖。
在 main 直接开发，完成后直接 push，不创建分支、worktree 或增加审核门槛。

## 接口与语义

- `WithStack(err error) error`：nil 返回 nil；树中已有 errx 堆栈时复用，否则记录调用位置，最多 64 帧。
- `Stack(err error) []Frame`：返回深度优先先序找到的首个堆栈副本。
- `WithFields(err error, fields map[string]any) error`：保留 Error 文本和 Unwrap，复制字段 map；nil 错误返回 nil。
- `Fields(err error) map[string]any`：汇总所有分支字段，外层和先访问的分支优先，返回独立 map；值为浅复制。
- `Walk(err error) iter.Seq[error]`：先序深度优先，支持 Unwrap() error 和 Unwrap() []error；保留共享节点在不同路径的出现，不做去重。
- `Leaves(err error) iter.Seq[error]`：按上述顺序遍历所有叶子原因；nil 无结果。
- `CodeError{Code, Message string; Err error}`：Error 仅返回 Message（空时回退 Code 或原始错误），Unwrap 保留原始链；不自动以相同错误码建立 errors.Is 等价关系。
- `CodeOf(err error) string`：返回首个非空业务码；支持 ErrorCode() string 的外部错误。
- `Describe(err error) Description`：返回 Message、Code、合并 Fields、首个 Stack 和 Nodes；Nodes 通过 Parent 索引保留完整树形关系，根 Parent 为 -1。显式包含各节点的原始错误文本，适用于内部诊断。

Frame 包含 Function、File、Line，可 JSON 序列化。Description 支持 slog.LogValuer，也可直接传给 LogAcc。
所有错误类型、Error/Unwrap 方法及构造包装函数集中到 error.go；常量集中到 consts.go。
额外数据不自动进入 Error 文本，不自动打印日志，不替换现有包的错误类型。
遍历与标准 errors 一样要求无环的有效错误树；nil 子节点忽略。字段值中的指针、map、切片由调用方负责同步。
